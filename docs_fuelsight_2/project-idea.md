# FuelSight v2

## Контекст
`docs_fuelsight/` фиксирует уже собранный MVP как `as-built` состояние.  
`docs_fuelsight_2/` описывает целевую улучшенную версию проекта, которую нужно реализовывать поверх текущей кодовой базы без потери совместимости по маршрутам, ролям и API envelope.

## Проблема
Текущий MVP уже закрывает базовый поток `login -> import/demo-data -> dashboard -> analytics -> forecast -> news`, но для production-like впечатления ему не хватает:
- более ясной аналитической визуализации для не-технического пользователя;
- более сильного ML-контура с CatBoost как основным режимом, а не просто опцией;
- реалистичных начальных данных и внешних индикаторов;
- analyst-first демонстрационного сценария;
- полноценного news/chat контура вместо fixture + `template_rag`;
- операционного режима для защиты диплома с управляемой деградацией.

## Целевая версия v2
FuelSight v2 остаётся локальной системой для одной точки продаж, но становится ближе к рабочему внутреннему продукту:
- analyst видит чистый бизнес-интерфейс без технических оговорок про синтетику;
- графики объясняют не только "что произошло", но и "почему это важно";
- CatBoost используется как primary model для горизонтов `1/7/30`, а baseline служит только benchmark;
- Airflow ежедневно обновляет признаки и внешние индикаторы, а еженедельно переобучает модель;
- news и chat работают с реальными сохранёнными материалами и обязательными citations;
- защита диплома может проходить как в `cloud-enhanced`, так и в `offline-safe` режиме.

## Что меняется относительно MVP
- UI остаётся на тех же маршрутах, но получает единый `chart design system`, summary-блоки и status badges.
- Импорт и начальные данные получают нейтральный пользовательский язык вместо явного `demo/generated`.
- Login и основной пользовательский путь смещаются в сторону `analyst`.
- External data перестают быть stub-контуром и становятся частью стандартного pipeline.
- Forecast/backtest API возвращают richer metadata: freshness, baseline comparison, feature sources, retrain status.
- News/chat используют hybrid стратегию: real provider + local cache + LLM fallback ladder.

## Ценность v2
- Система выглядит не как учебный стенд, а как локальный аналитический продукт.
- Комиссии можно показать не только интерфейс, но и зрелый контур эксплуатации: качество данных, freshness модели, режим деградации, воспроизводимый demo-run.
- Архитектура остаётся реалистичной для диплома: без multi-tenant SaaS, биллинга и лишней платформенной сложности.

## Верхнеуровневый пользовательский поток
1. Пользователь входит под `analyst@fuelsight.local` и попадает на `/dashboard`.
2. Видит KPI, краткое бизнес-объяснение, проблемные зоны и модельные/данные badges.
3. Переходит в `/analytics/sales` и `/analytics/margin`, где графики уже содержат пояснения, зоны риска и reference overlays.
4. На `/forecast` получает base/scenario forecast, качество модели, freshness и сравнение с baseline.
5. На `/news` видит реальную сводку, режим провайдера и чат с обязательными источниками.
6. `admin` при необходимости отдельно открывает import/retrain/refresh контур, не смешивая его с analyst demo flow.

## Границы v2
- Всё ещё одна точка продаж, без `stations`.
- Base URL остаётся `/api/v1`.
- Envelope ответа не меняется: `{ data, error, meta }`.
- Роли сохраняются: `admin`, `analyst`.
- LLM остаётся опциональным: при отсутствии cloud key продукт обязан деградировать в `local_llm` или `retrieval_only`.

## Критерии успеха
- В репозитории есть полный набор `docs_fuelsight_2/`, зеркальный по структуре текущим docs.
- Документация v2 decision-complete и напрямую опирается на gaps текущей реализации.
- `memory-bank/` отражает новый фокус: v1 как текущая база, v2 как целевая следующая стадия.
- Для каждой ключевой фичи описаны UX, API, данные, операционный режим и тестовые сценарии.
